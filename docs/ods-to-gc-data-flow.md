# ODS → GenericCode Data Flow

How the Crane-ods2obdgc XSLT pipeline transforms Google Sheets ODS exports
into GenericCode (.gc) XML files. Reverse-engineered from the XSLT source.

## Pipeline Overview

```
UBL-Library-Google.ods  ─┐
                         ├──► Saxon + Crane-ods2obdgc.xsl ──► UBL-Entities-2.5.gc
UBL-Documents-Google.ods ┘         + ident-UBL.xml
                                   + massageModelName.xml
                                   + sheet-name-regex filter

(same inputs)            ──► Saxon + Crane-ods2obdgc.xsl ──► raw.gc
                               ──► Saxon + gc2endorsed.xsl ──► UBL-Endorsed-Entities-2.5.gc
```

## Input Files

| ODS File | Data Sheets | Excluded Sheets | Content |
|----------|-------------|-----------------|---------|
| **UBL-Library-Google.ods** | 1 (`CommonLibrary`) | `Logs-sheet` | Common library components shared across all document types |
| **UBL-Documents-Google.ods** | 101 (one per document type) | `Logs-sheet` | One sheet per UBL document type (Invoice, Order, CreditNote, etc.) |

The XSLT opens both ODS ZIPs, reads `content.xml` from each, and unions all
`table:table` elements. The regex filter excludes sheets starting with "Logs":

```
^([Ll]($|[^o].*|o($|[^g].*|g($|[^s].*))))|^[^Ll].*
```

## Output Structure: Three Sections

### 1. `<Identification>` — External metadata (NOT from ODS)

Comes entirely from `ident-UBL.xml`, generated by the conversion script.
Contains ShortName, Version, URIs, Agency info. No ODS data involved.

```xml
<Identification>
  <ShortName>UBL-2.5-CSD02</ShortName>
  <LongName>UBL 2.5 CSD02 Business Entity Summary</LongName>
  <Version>2.5</Version>
  <CanonicalUri>urn:oasis:names:specification:ubl:BIE</CanonicalUri>
  ...
</Identification>
```

### 2. `<ColumnSet>` — Column definitions (from ODS header rows)

**27 columns total:**

- **Column 1: `ModelName`** — SYNTHETIC, hardcoded by the XSLT
  (`Crane-ods2obdgc.xsl:278`). Not from any ODS cell. Always `Use="required"`.

- **Columns 2–27** — Derived from the **first row (header row)** of ALL
  sheets. The XSLT groups headers across all sheets by text content, strips
  non-word characters (`\W+`) to create `Id`/`ShortName`, keeps original
  text as `LongName`. All are `Use="optional"` except `DictionaryEntryName`
  which is `Use="required"` and becomes the `<Key>`.

### 3. `<SimpleCodeList>` → `<Row>` elements (the actual data)

For each non-excluded sheet, for each data row (row 2 through `END` marker
or last row), skipping empty rows.

## Sheet Tab Name → ModelName Lengthening

The XSLT parameter `lengthen-model-name-uri` points to `massageModelName.xml`,
which defines regex passes applied **in reverse order** to expand abbreviated
Google Sheets tab names (limited to 31 chars) into full UBL model names:

| Pass (reverse order) | Find → Replace | Example |
|---------------------|----------------|---------|
| 6 (applied first) | `Prcd` → `Procedure` | `UnsubscribeFromPrcd…` → `UnsubscribeFromProcedure…` |
| 5 | `Sgnt` → `Signature` | `SgntPolicy` → `SignaturePolicy` |
| 4 | `Txp` → `Transport` (before non-'a') | `TxpExecutionPlan` → `TransportExecutionPlan` |
| 3 | `Qlfctn` → `Qualification` | `TendererQlfctn` → `TendererQualification` |
| 2 | `Ctlg` → `Catalogue` | `CtlgDeletion` → `CatalogueDeletion` |
| 1 (applied last) | `(.+)` → `UBL-$1-2.5` | `Invoice` → `UBL-Invoice-2.5` |

**Full examples:**

| ODS Sheet Tab | → ModelName in .gc |
|---------------|-------------------|
| `CommonLibrary` | `UBL-CommonLibrary-2.5` |
| `Invoice` | `UBL-Invoice-2.5` |
| `Ctlg` | `UBL-Catalogue-2.5` |
| `TxpExecutionPlan` | `UBL-TransportExecutionPlan-2.5` |
| `QlfctnApplicationRequest` | `UBL-QualificationApplicationRequest-2.5` |
| `UnsubscribeFromPrcdRequest` | `UBL-UnsubscribeFromProcedureRequest-2.5` |

## Row Processing Logic

For each sheet, the XSLT (`gcExportSubset.xsl:c:emitGenericode`):

1. **Determines column count** from the last non-empty cell in row 1.
2. **Reads header row** (row 1) — builds column-name lookup array.
3. **Finds last data row** — either the row before a row containing just
   `END`, or the actual last row.
4. **Iterates rows 2 through last** — skips rows that are entirely empty.
5. **For each row, emits `<Row>`:**
   - `<Value ColumnRef="ModelName">` → lengthened sheet tab name (same for
     all rows in a sheet)
   - For each column position 1..N where both the header and cell are
     non-empty: `<Value ColumnRef="{headerId}"><SimpleValue>{cellText}</SimpleValue></Value>`
   - Empty cells are **omitted** (not emitted as empty values)

**Row comment:** Each `<Row>` gets an XML comment `<!--N-->` with the
1-based row number from the spreadsheet (e.g., `<!--2-->` for first data row).

## Endorsed File Pipeline

The Endorsed file uses a **two-stage** pipeline:

**Stage 1:** Run the exact same Crane XSLT on the same ODS pair (with a
different `ident-UBL-Endorsed.xml`). Produces an identical raw .gc.

**Stage 2:** `gc2endorsed.xsl` filters the raw .gc:

| Rule | Effect |
|------|--------|
| Remove `Endorsed*` columns | Strips `EndorsedCardinality`, `EndorsedCardinalityRationale` from ColumnSet |
| Remove `Endorsed*` values | Strips corresponding `<Value>` elements from rows |
| Remove rows with `EndorsedCardinality='0'` or `'0..0'` | Deprecated BIEs excluded |
| Remove ABIE cascades | If an ABIE has `EndorsedCardinality='0'`, ALL rows with that `ObjectClass` are removed |
| Replace Cardinality | Where `EndorsedCardinality` exists, its value replaces `Cardinality` |

## Tracing .gc Changes Back to ODS Edits

Every change in the .gc file maps to exactly one type of ODS edit:

| .gc Change | ODS Source |
|-----------|-----------|
| `<SimpleValue>` text change in a `<Value>` | Cell edit in specific sheet, specific column, specific row |
| `ModelName` value change | Sheet tab renamed |
| Column `Id`/`ShortName` change | Header cell text changed in row 1 |
| `<Row>` added/removed | Row inserted/deleted in a specific sheet |
| Block of rows with same `ModelName` added/removed | Entire sheet added/deleted |
| `ColumnRef` attribute values change | Header cell text changed (affects all rows) |

**Example:** If a revision diff shows "cell E15 in sheet 'Invoice' changed
from '0..1' to '1'", that maps to a `<Row>` with
`ModelName=UBL-Invoice-2.5` (row 15 from that sheet) where
`EndorsedCardinality` changed from `0..1` to `1`.

## Matching Official Releases to ODS Revisions

By comparing the DictionaryEntryName sets and cell values in the official
released .gc files against the ODS revision diffs, we can identify exactly
which library ODS revision was used to build each release.

### Method

1. Extract all CommonLibrary DENs from the official .gc file
2. Extract DENs from a known ODS revision (rev-1843, which we have downloaded)
3. Walk backwards through the diff artifacts, undoing row adds/removes, until
   the reconstructed DEN set exactly matches the official .gc
4. Narrow further by checking cell-level diffs (Definition edits etc.) to
   find the exact revision before any content divergence
5. **Verify:** Download the candidate ODS revision from the public Drive folder,
   run the full Crane XSLT conversion, and compare the generated .gc against
   the official .gc cell-by-cell

|---------|----------------|-------------------|----------|
| **csd01-UBL-2.5** | **rev-1533** | **rev-1294** | Full pipeline validation: downloaded both ODS revisions, ran Crane XSLT conversion, generated .gc matches official .gc EXACTLY. |
| **csd02-UBL-2.5** | **rev-1999** | **rev-2190** | Full pipeline validation: downloaded both ODS revisions, ran Crane XSLT conversion, generated .gc matches official .gc EXACTLY. |

### csd01 detail: rev-1533

- **DEN count:** 3151 (exact match with csd01 .gc)
- **Verified:** Downloaded rev-1533 from public Drive folder, ran Crane XSLT conversion, compared all 3151 CommonLibrary cell values — **zero differences**
- **Why not rev-1543?** Initial DEN-only matching found rev-1543 (same 3151 DENs), but 7 Definition values differed: revisions 1533→1539 added "customs" to 7 Consignment Office definitions. The official csd01 was built before those edits.
- **Revision timeline:**
  - rev 1531→1532: Added "Credit Note Line. Work Report_ Line Reference" row
  - rev 1532→1533: Renamed "Sub_ Work Statement Line" → "Sub_ Work Report Line"
  - **rev 1533: ← csd01 library snapshot (confirmed)**
  - rev 1533→1534: First "customs" edit (Office Of Entry definition)
  - rev 1534→1539: Six more "customs" definition edits
  - rev 1543→1544: Added "Office Of Transit" row (DEN count becomes 3152)
- **30 DENs added later** (present in rev-1843 but not csd01): Radioactive Material group (7 DENs), Hazardous Item extensions (6), Electronic Address (4), Energy Consumption Allocation (4), Payment Means blockchain/rail (2), and others
- **Column structure:** All 26 data columns present including new-in-2.5 columns (EndorsedCardinality, EndorsedCardinalityRationale, DeprecatedDefinition, LastChanged)

### csd02 detail: rev-1999

- **DEN count:** 3183 (exact match with csd02 .gc)
- **Verification:** Direct cell-by-cell comparison against downloaded ODS — zero differences
- **Context:** Rev 1999 is one of the 4 library ODS snapshots we have on disk
- **Forward-walk confirmation:** Starting from csd01 (rev-1533), walked forward

- **csd01→csd02 delta:** 32 new DENs, 0 removed, 142 cell changes across

- **Editing pattern:** Changes were applied one cell per revision (one
